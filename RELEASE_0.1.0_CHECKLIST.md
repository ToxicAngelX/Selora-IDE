## 2. Draft asset contract

The release workflow creates a **draft** GitHub Release with exactly these
uploaded assets:

| Asset | Required property |
|---|---|
| `Selora-IDE-Setup-0.1.0.exe` | Inno Setup installer, per-user, `>=` 5 MiB, signature `NotSigned` unless signing secrets exist |
| `Selora-IDE-Setup-0.1.0.exe.sha256` | One ASCII line: `<64 lowercase hex><two spaces>Selora-IDE-Setup-0.1.0.exe` |
| `Source code (zip)` | Generated by GitHub from the tag; not uploaded by the workflow |
| `Source code (tar.gz)` | Generated by GitHub from the tag; not uploaded by the workflow |

Not attached on purpose: PDB/symbol files, a portable ZIP, a machine-wide MSI,
macOS/Linux builds, and a fixed-version WebView2 runtime. Lite ships the
Evergreen bootstrapper inside the installer instead.

Expected local dry-run hash:

| Artifact | Size (bytes) | SHA-256 |
|---|---|---|
| `Selora-IDE-Setup-0.1.0.exe` | 9,408,027 | `95b2f4deb29fa851215fd08fd6f6a88918ec46757884b19866d4a829882360b0` |
| `Selora-IDE-Setup-0.1.0.exe.sha256` | 94 | one line, same hash |
| `target\release\selora-desktop.exe` (input) | 18,875,904 | `acab5f75eb34a53525918c8b8e770f902adf8aa5c622419e3e13c4c1cc13cfd5` |

The workflow-generated `.sha256` must match this value only if the workflow
reproduces the local build byte-for-byte. Cargo and Inno builds are not
guaranteed reproducible, so treat the local hash as a sanity reference, not as
the expected CI hash. Always verify the draft's own `.sha256` against the
downloaded `.exe`.

## 3. What the hardened pipeline now checks

CI (`.github/workflows/ci.yml`, every push and PR):

1. `scripts/check-release-metadata.ps1` - version agreement, changelog on tag
   pushes, repository slug agreement, update-check derivation, CSP.
2. frontend `npm ci`, typecheck, Vitest, production build, `dist/index.html`.
3. `cargo fmt --all -- --check`.
4. `cargo clippy --workspace --all-targets --locked -- -D warnings`.
5. `cargo build --workspace --locked`.
6. `cargo test --workspace --locked`.
7. pinned `cargo-deny 0.20.2`, then `cargo deny check`.

Release (`.github/workflows/release.yml`, `v*.*.*` tag):

1. Tagged commit must be an ancestor of `origin/main`.
2. `check-release-metadata.ps1 -Tag <tag>` before anything is built.
3. Same frontend, fmt, clippy, deny, test, and release-build gate as CI.
4. Tags a binary whose `VCRUNTIME140.dll` import is proven with `dumpbin`; the
   staged DLL list must have `[Files]` entries in the installer.
5. Downloads and signature-checks Microsoft's WebView2 bootstrapper.
6. Installs pinned Inno Setup 6.7.1, resolves ISCC with
   `installer/find-iscc.ps1` (no hard-coded Program Files path).
7. Compiles with an absolute `/O<repo>\installer\output` and fails if the
   setup is missing or under 5 MiB.
8. Optional signing; then asserts `Valid` with a certificate, `NotSigned`
   without one.
9. Writes and re-verifies the checksum line, then re-hashes the installer.
10. Refuses to attach to an already-published release.
11. Creates the **draft** release, then verifies `isDraft`, both asset names,
    upload size, and a `gh release download` round-trip hash.

## 5. Owner-only steps (not performed by the agent)

These are outside the agent's authority. Do not skip the order.

1. **Publish the repository.** `ToxicAngelX/Selora-IDE` returned HTTP 404 on
   2026-10-27, so the update check cannot resolve yet, and the release
   workflow has no `origin/main` to verify. Either create that repository and
   push `main`/the tag, or change the slug in the four places enforced by
   `scripts\check-release-metadata.ps1`:
   `Cargo.toml`, `frontend/package.json`, `installer/selora-ide.iss`, and
   `docs/mkdocs.yml`. The Rust and frontend URLs derive from the first two.
2. **Install Inno Setup durably** (optional but recommended):
   `winget install JRSoftware.InnoSetup`. The current compiler is an extracted
   copy under `%TEMP%\innosetup-6.7.3`; `prebuild.bat` finds it through the
   uninstall registry, but a temp cleanup removes it.
3. **Run the local gates** from section 4 (fill in the placeholders) and the
   clean-VM test in `RELEASE.md` section 8.
4. **Tag from merged `main`:**
   `git tag v0.1.0` then `git push origin v0.1.0`. The tag must point at a
   commit already on `main`.
5. **Optional signing.** Add repository secrets `SIGNING_CERT_BASE64` and
   `SIGNING_CERT_PASSWORD`; set repository variable `SIGNING_REQUIRED=true`
   only if a missing certificate must fail the release. Without secrets the
   installer is `NotSigned` and SmartScreen shows "Windows protected your PC".
6. **Watch the release workflow.** It must finish with
   "Verify draft release assets" green. If it fails, fix and re-run; it will
   reuse the draft. Do not hand-edit a published release.
7. **Download and verify** the draft assets:

   ```powershell
   gh release download v0.1.0 --pattern 'Selora-IDE-Setup-0.1.0.exe*'
   Get-FileHash .\Selora-IDE-Setup-0.1.0.exe -Algorithm SHA256
   Get-Content .\Selora-IDE-Setup-0.1.0.exe.sha256
   ```

   The `Get-FileHash` value must equal the first field of the `.sha256` file.
8. **Clean-VM smoke test:** Windows 11, plus Windows 10 without WebView2.
   Confirm no UAC prompt, the Start Menu shortcut, Settings -> Apps uninstall,
   the `.txt` "Open with" entry, and the full `RELEASE.md` section 8 smoke list.
9. **Publish manually.** Edit the release notes, uncheck "Set as a draft", and
   publish. No workflow publishes automatically.

The agent did not create a repository, tag, release, certificate, or secret,
and did not upload or publish any artifact.
